# A100 80GB PCIe course results

本文记录课程实验的测量边界与解释。数字来自 `sc4` 的 A100 80GB PCIe；它们用于支撑教学叙事，不是 GPU 架构常数或跨环境性能保证。

## Comparison contract

自写 kernel：

- FP32 CUDA Core / FFMA；
- 无 Tensor Core / TF32；
- 无 `cp.async`、TMA；
- 无 double buffering、software pipeline；
- 所有版本共用同一 benchmark 和 correctness harness。

cuBLAS baseline：

```cpp
cublasSetMathMode(handle, CUBLAS_PEDANTIC_MATH);
cublasGemmEx(..., CUBLAS_COMPUTE_32F_PEDANTIC, CUBLAS_GEMM_DEFAULT);
```

因此这里比较的是 CUDA Core FP32 kernel 与 pedantic FP32 cuBLAS，不是与 TF32 Tensor Core cuBLAS 比较。

## 4096³ performance evolution

| Version | Main change | TFLOP/s | % of cuBLAS |
|---|---|---:|---:|
| V1 | intentionally bad warp mapping | 0.43 | 3.0% |
| V0 | coalesced naive | 2.11 | 14.6% |
| V2 | shared-memory tiling | 3.95 | 27.4% |
| V3 | 1D register tiling | 6.02 | 41.8% |
| V4 | 2D register tiling | 9.38 | 65.1% |
| V5 | V4 + vectorized loading | 10.70 | 74.3% |
| V5b | V4 + bank-aware ownership | 10.24 | 71.1% |
| V6 | vectorized + bank-aware | **10.97** | **76.1%** |
| cuBLAS pedantic | FP32 baseline | **14.41** | 100% |

V3→V4 提升约 56%，是主线中最大的一步。对这个 A100 FP32 GEMM，2D register tiling 不是为了让代码外观接近 CUTLASS，而是达到较高 compute throughput 的必要机制。

V4/V5/V5b/V6 构成两因素消融。V4→V6 同时改变 vectorized loading 与 ownership，不能把完整 17% 的累计提升都归因于 bank conflicts。

## 8192³ result and caveat

V6 在一轮 8192³ steady-state/hot-cache 测试中曾达到 pedantic FP32 cuBLAS 的 90.4%。2026-07-28 使用本仓库同一代码、CUDA 13、3 次 warmup 和 10 次计时，在两张空闲 A100 上复验：

| Device/run | V6 | cuBLAS pedantic | Ratio |
|---|---:|---:|---:|
| A100 device 0 | 11.70 TFLOP/s | 14.49 TFLOP/s | 80.7% |
| A100 device 1 | 15.38 TFLOP/s | 19.04 TFLOP/s | 80.8% |

两个 device 的绝对吞吐差异很大，但相对比例接近；先前的 90.4% 未在本次复验中重现。可能影响历史结果的因素包括：

- 更大的 grid 减少 partial-wave/tail effect；
- mainloop 占比更高，launch 与 epilogue 更容易摊薄；
- pedantic cuBLAS 的算法选择与运行期 clock 状态；
- benchmark 重复使用同一 A/B buffer，属于 steady-state/hot-cache 测试。

因此课程表述为：

> 对 A100 上大而规则的方阵，这条不使用 Tensor Core 和流水线的教学路线可达到 pedantic FP32 cuBLAS 的较高比例；4096³ 的约 76% 是当前稳定、适合复现的代表值。8192³ 当前复验约为 81%，90.4% 只作为历史观测保留。

不表述为“该 kernel 通用达到 cuBLAS 90%”。

## Two compute roofs

A100 80GB PCIe 的 datasheet FP32 CUDA Core peak 约为 19.5 TFLOP/s。本次 NCU profile 中运行期 SM clock 约为 1.06 GHz，低于最大 boost 1.41 GHz。按频率粗略修正：

\[
P_{roof, measured-clock}
=19.5\times\frac{1.06}{1.41}
\approx14.7\ \text{TFLOP/s}
\]

| Implementation | TFLOP/s | Datasheet roof | Frequency-scaled roof |
|---|---:|---:|---:|
| V6 | 10.97 | 56% | ≈75% |
| cuBLAS pedantic | 14.41 | 74% | ≈98% |

这解释了为何 cuBLAS 看似只有标称峰值的 74%，但 profile 已接近当前 clock 下的 compute saturation。课程应同时展示 datasheet roof 与 measured-frequency roof，并明确第二个只是按观测频率做的近似缩放。

NCU 对 V6 报告 `Compute (SM) Throughput = 74.8%`，与上述频率修正后的比例相当一致。

## Global-to-shared roofline

V6 的 CTA tile 为 `128×128×8`。以每个 CTA 从 global 搬入 A/B tile、再在 shared/register 中复用为边界：

\[
AI_{global\rightarrow shared}
=\frac{2\cdot128\cdot128\cdot8}
{4(128\cdot8+8\cdot128)}
=32\ \text{FLOP/byte}
\]

若 A100 PCIe HBM bandwidth 取约 1.9 TB/s：

\[
P_{HBM}=1.9\ \text{TB/s}\times32\ \text{FLOP/byte}
\approx60.8\ \text{TFLOP/s}
\]

它高于 19.5 TFLOP/s 的 FP32 compute roof。因此充分 tiled 后，V6 理论上不应由 HBM bandwidth 限制。NCU 观测支持这一判断：

| Metric | V6 |
|---|---:|
| DRAM throughput | 3.21% |
| Compute throughput | 74.82% |
| L1/TEX throughput | 38.47% |

## Bottleneck migration

```text
naive
  global/cache traffic and exposed latency
    ↓
shared tiled
  shared traffic and barriers
    ↓
1D register tiled
  improved shared reuse, insufficient ILP
    ↓
2D register tiled
  high compute reuse, bank conflicts/register pressure
    ↓
bank-aware vectorized
  compute-heavy; issue/pipeline limitations remain
```

V6 的剩余限制包括 FP32 compute/issue、低 occupancy 下的 eligible warp 数量、single-buffer load/compute phases、barriers、剩余 shared/LSU 指令，以及未做 software pipeline 暴露出的等待。

## V4 to V6 profiler evidence

| Metric, 4096³ | V4 continuous | V6 striped + vectorized |
|---|---:|---:|
| Shared load bank conflicts | 268,438,491 | 14,854 |
| Shared load wavefronts | 671,091,675 | 402,668,909 |
| Shared store bank conflicts | 103,734,837 | 1,375,287 |
| Runtime | 14.65 ms | 12.53 ms |
| Throughput | 9.38 TFLOP/s | 10.97 TFLOP/s |
| L1/TEX throughput | 71.9% | 38.5% |
| Compute throughput | 64.0% | 74.8% |
| Eligible warps/scheduler | 0.92 | 1.32 |
| Issued warps/scheduler | 0.40 | 0.49 |

这些 counters 与“shared/L1TEX pressure 降低、更多 warps eligible、compute-side utilization 上升”一致。它们本身不证明所有收益来自某一个机制；归因必须结合 V4/V5/V5b/V6 消融。

## Acceptance target

4096³ 的课程最终验收：

- ≥ 10.5 TFLOP/s；
- ≥ pedantic FP32 cuBLAS 的 70%；
- irregular correctness cases 通过；
- no spills；
- shared load conflicts approximately zero。

当前 V6 为 10.97 TFLOP/s、cuBLAS 的 76.1%，达到该标准。
